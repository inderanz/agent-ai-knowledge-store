## How to evaluate a repository before using it

1. Read the local README, licence, security policy, contribution guide, manifest, and workflows.
2. Confirm that the repository solves the measured bottleneck in your chosen workflow.
3. Create an isolated proof and a representative task/failure test set.
4. Review dependency and model licences, vulnerabilities, data handling, network calls, telemetry, secrets, and update strategy.
5. Compare the default against only one alternative using task success, latency, cost, operability, and user outcome.
6. Record the decision and an exit plan; do not make a repository a permanent platform dependency by accident.

## Clone layout

Each repository is shallow and blob-filtered. The sparse review checkout includes top-level README, licence, security/contribution files, package manifests, and workflows. Use `git -C <directory> sparse-checkout add <path>` to fetch additional paths deliberately, or open the upstream repository from the [clone manifest](../whatsapp-links-Inder-Australia-2026-08-04-research.md#clone-manifest).
