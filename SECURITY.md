# Security policy

Do not place customer data, credentials, tokens, private endpoints, internal architecture, security findings, or vulnerability reproduction details in public issues or pull requests.

For repository-content problems that do not disclose an exploitable vulnerability—such as an inaccurate IAM recommendation, stale maturity label, or unsafe example—open an issue with the affected file, official source, impact, and proposed containment. Mark affected content Draft until reviewed when production safety could be affected.

The repository owner has not yet published a private vulnerability-reporting channel. Until one is configured, do not disclose sensitive vulnerability details in this repository; use the relevant official Google Cloud or upstream project security-reporting process.

Documentation examples must use placeholders and short-lived workload identity. Service-account keys and committed secrets are prohibited.
