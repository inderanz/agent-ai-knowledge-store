# Author Enterprise Chapter

Create a candidate change, never an unreviewed production claim.

## Workflow

1. Require a validated evidence packet and impact manifest.
2. Read [references/chapter-contract.md](references/chapter-contract.md) and the repository style guide.
3. Preserve the repository classifications for official capability, architecture recommendation, and field pattern.
4. Write from customer outcome to decision, architecture, implementation, verification, operation, and exit.
5. Put exact citations next to the claims they support. Cite tagged code or a full commit for implementation behavior.
6. State Preview, allowlist, regional, quota, pricing, and support limitations locally.
7. Add runnable commands only when their prerequisites, placeholders, expected result, failure result, cleanup, and rollback are defined.
8. Update the evidence ledger and `verified_at` only for sources actually reviewed.
9. Leave the chapter Draft unless the repository's independent qualification contract is satisfied.

## Output

Stage candidate files plus a manifest listing evidence, changed claims, assumptions, unresolved questions, required tests, and reviewers. Never claim that generated or local test evidence represents a customer deployment.
