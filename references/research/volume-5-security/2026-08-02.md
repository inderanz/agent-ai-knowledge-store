# Volume 5 research record — 2 August 2026

Only official Google documentation was used for Google product claims. This is
a dated discovery record, not a substitute for deployment-time verification.

| Source | Checked conclusion | Volatility / implementation consequence |
|---|---|---|
| [Govern your agents](https://docs.cloud.google.com/gemini-enterprise-agent-platform/govern) | Registry, identity, Gateway, policies, security and oversight are separate governance surfaces | qualify each selected surface |
| [Agent Gateway overview](https://docs.cloud.google.com/gemini-enterprise-agent-platform/govern/gateways/agent-gateway-overview) | documented ingress/egress modes use Registry, identity, delegated policies and observability | topology- and mode-specific validation |
| [Agent Identity](https://docs.cloud.google.com/gemini-enterprise-agent-platform/govern/agent-identity-overview) | authority/authentication combinations differ; three-legged OAuth delegation is Preview | never claim one product-wide maturity |
| [Agent Registry](https://docs.cloud.google.com/gemini-enterprise-agent-platform/govern/agent-registry) | provides centralized inventory/discovery for agents, tools and MCP servers | registration is not authorization |
| [Model Armor on Gateway](https://docs.cloud.google.com/gemini-enterprise-agent-platform/govern/configure-model-armor) | templates can inspect documented Gateway request/response paths and block/redact | content control remains layered with action policy |
| [Release notes](https://docs.cloud.google.com/gemini-enterprise-agent-platform/release-notes) | 18 June 2026 announces Agent Gateway GA; 24 June announces Model Armor for Gateway GA | feature pages and exact modes still govern selection |
| [Workload Identity Federation](https://docs.cloud.google.com/iam/docs/workload-identity-federation) | external workloads can exchange federated identity instead of managing service-account keys; attribute restrictions are recommended | pipeline identity design and negative tests |
| [VPC Service Controls](https://docs.cloud.google.com/vpc-service-controls/docs/overview) | service perimeters reduce exfiltration risk for supported services | document coverage and exceptions, do not overclaim |
| [Secret Manager best practices](https://docs.cloud.google.com/secret-manager/docs/best-practices) | least privilege, rotation and secure access practices apply | exercise live rotation/revocation |
| [Agent Platform Threat Detection](https://docs.cloud.google.com/security-command-center/docs/agent-platform-threat-detection-overview) | current SCC feature is Preview for supported Agent Runtime threats and has tier constraints | detective/compensating only; customer acceptance |
| [Use Agent Platform Threat Detection](https://docs.cloud.google.com/security-command-center/docs/use-agent-platform-threat-detection) | enablement, finding review and CLI-argument reporting behavior affect privacy/operations | SOC runbook and data review |
| [Software supply-chain security](https://docs.cloud.google.com/software-supply-chain-security/docs/overview) | Google provides a portfolio for source/build/artifact/deploy security | bind actual controls to immutable release evidence |

Observed documentation tension: broad overview wording and current release notes
can expose different maturity descriptions while pages are updated. The handbook
therefore records source URL, feature, mode, date, region and customer acceptance
instead of collapsing maturity into a platform label.

No third-party blog or inferred product behavior is represented as official fact.
No customer project, IAM binding, policy, Gateway, Registry, template or detector
was modified during research.
